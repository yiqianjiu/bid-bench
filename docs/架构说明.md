# 架构说明（bid-bench / 投标业务工作台）

> 版本 1.2.5。这是一份给「想改代码的人」看的文档，讲清每个文件管什么、一次点击在后端怎么走、AI 在哪些地方被调用、数据存在哪、要加功能该动哪。

---

## 一、总体结构

~~~
bid-bench/
├── app/
│   ├── server.mjs          HTTP 服务与全部路由（零框架，node:http）
│   ├── lib/                业务模块（29 个 .mjs）
│   ├── web/                前端单页（index.html + app.js + style.css + indep.html/indep.js，无构建）
│   └── config.example.json 配置模板（复制成 config.json 后填 Key）
├── scripts/                install.bat / start.bat / stop.bat
├── 数据/                    运行时生成：workbench.db + 文本/分析/制作/核查缓存
├── 项目/                    运行时生成：每个项目一个文件夹
├── 归档/                    项目关闭后归档到这里
└── docs/                    本文档等
~~~

设计约束（有意为之）：

1. **零依赖框架**：只有 4 个 npm 依赖（docx / mammoth / pdfjs-dist / pdf-to-img），其余全用 Node 内置能力（node:http、node:sqlite、node:zlib）。
2. **前端不打包**：app/web/app.js 是原生 JS 单页，改完刷新浏览器即生效。
3. **文件优先**：每个模块的中间结果都落 JSON 到项目目录，数据库只存项目索引；即使数据库坏了，项目文件夹里的东西还在。
4. **AI 可选**：没填 Key 时规则类功能（解析、生成框架、格式核查、行动清单）全都能用，只有「AI 分析 / 写正文 / 逐条核查 / 模拟评标」需要 Key。

## 三、一次请求怎么走

### 3.1 上传招标文件

~~~
浏览器 POST /api/projects/:id/files (multipart)
  → server.mjs 解析 multipart，落盘 项目/编号_项目名/01招标文件/
  → extract.mjs 抽文字（pdfjs）→ text.mjs 写缓存 数据/文本/<fileId>.json
  → files 表更新 pages / textChars / extracted
~~~

### 3.2 招标分析（耗时任务）

~~~
POST /api/projects/:id/analyze  → 建任务，返回 taskId（立即 202）
后台：ensureText → splitSegments(每段 ≤N 页) → 分段并发调 AI
     → 14 个板块各自归并（merge 阶段）→ 数据/分析/<pid>.json
GET /api/tasks/:taskId 轮询 {state: running|done|error, message}
~~~

要点：分析结果一旦落盘，后面写正文、核查、递交清单全都读它，不会重复花钱分析。

### 3.3 生成标书正文

~~~
POST /api/projects/:id/draft/:doc/chapter/:cid  {action:"generate"}
  → draft.mjs generateChapter()
    → clauseKeysFor(docKey,title) 选板块（技术类→tech/deliver/business…）
    → 按相关度排序、字数封顶 24000，再恢复招标原文顺序
    → 若本章 role 为 tech/biz：先取已确认的专家画像（profile.mjs），
      没有就先返回 needProfile，前端弹窗确认后才继续
    → prompt.mjs draftUserPrompt() 拼提示词（叠加专家身份 + 知识库参考）
      → callText(temperature 0.5)；重要章节字数低于下限时自动再要一版
    → checkCoverage() 算「覆盖 N/M 条」→ 写回 制作/<pid>.json
~~~

### 3.4 文件核查

~~~v1.2.3：全程异步，进度可观察、可停止
POST /api/projects/:id/check  → 任务 t（带 _abort、stage、docIndex、lastTickAt）
  → 同项目已有 running 任务：
       距今 < STALL_MS(3 分钟) → 直接返回它（前端接回进度）
       否则判 stalled 并 abort，另开新任务
  → listSources()：列候选（四道闸见 3.12），只核查 final
  → 每份文件 checkOneDoc(project, src, analysis, {signal, onProgress, onStage})：
       docx/doc → docxToPdfAsync()（子进程；超时/取消抛 CONVERT_TIMEOUT / CONVERT_CANCELLED）
       成功 → extractPdfText + getPageInfo
       超时 → 降级：textPagesFallback 只抽文字，degraded=true，checksOmitted 记三项排版检查
  → ruleCheck()：空白页 / 页码 / 封面要素 / 占位 / 日期 / 项目名称编号
  → aiRequirementCheck()：328 条要求分批比（每批 ≤55 条，3 并发），每条给 2/1/0 + 证据 + 页码
  → aiDeepScore()：逐个评分项单独评分，先找索引表，没有就全文按页检索
  → 数据/核查/<pid>.json（停止的任务不写这个文件）
GET /api/check-tasks/:taskId 轮询（核查任务和分析的 /api/tasks 是两套接口）
POST /api/check-tasks/:taskId/stop → stopCheckTask()
~~~

### 3.5 导出 Word

四个 export*.mjs 都用 docx 库，共用两套排版约定：表格 FIXED 布局 + dxa 列宽（按列内容权重分配，每列 ≥600dxa）；表格行 cantSplit（不跨页断开）。导出后可选走 Word COM 转 PDF 检查排版。

### 3.6 独立编制（v1.1.2）

独立编制是一个**独立的浏览器窗口**（`/indep.html?p=&d=&c=`），只对 role 为 tech/biz 的章节开放。

~~~
打开窗口
  GET  /api/projects/:id/draft/:doc/chapter/:cid/indep
    → ensureSession()：没有会话就建，有就原样返回（对话/稿件/图表都在）
    → clientSession()：把图表 PNG 的绝对路径换成 /api/indep-image/<pid>/<cid>/<name>
                       （不把本机路径吐给浏览器）

编制生成
  POST …/indep/generate
    → buildContext()：按 docKey + 标题 + role 取条款，按 (★0.4 + 废标0.3 + 关键词重合) 排序、
      18000 字封顶，再恢复原文顺序；叠加已确认的专家画像与知识库参考
    → callJson(SYS_GEN)：返回 {title, text, charts[], hints[]}
    → 逐张 renderChart()（最多 6 张），失败的降级成「此处建议插入」提示
    → saveSession() 落盘 数据/独立编制/<pid>/<cid>.json

多轮对话
  POST …/indep/chat   → chatMessages([SYS_CHAT, 项目与稿件上下文, 最近 16 条, 新消息])
                       AI 只说打算怎么改，不动稿子
执行更新
  POST …/indep/update → 把最近 12 条对话塞进 genUserPrompt 的 extra，整稿重写；
                        同名图表复用不重画

改图
  POST …/indep/chart/:chartId  {instruction}  → reworkChart() 让 AI 重出 spec 再画
  POST …/indep/redocharts                      → 按现有 spec 全部重画（不调 AI）

导出
  POST …/indep/export  → exportDraftWord()：A4/宋体小四/1.5 倍行距、最简编号、
                         无封面目录页码；图按 afterText 前 12 字锚定插入；
                         未锚定的图与提示放文末附录；表格是真正的 Word 表格
  POST …/indep/writeback → 把稿件写回章节 body（source='ai', fromIndep=true）
~~~

图表链路：`chart.mjs` 的 buildSvg() 支持 flow / arch / gantt / timeline / line / bar / sequence / org 八种，table 走 normalizeTable 直接出表格不渲染 PNG；svgToPng() 写临时 HTML 到 os.tmpdir()，用 Chrome/Edge 的 `--headless=new --screenshot` 截成 PNG（40 秒超时）。**AI 只输出结构化描述，不产图**，这是能力边界也是安全边界——图上数值必须来自招标文件原文、用户补充或 AI 在其基础上推导的内容。

### 3.7 关闭归档门禁与只读（v1.1.2）

~~~
GET  /api/projects/:id/close-status
  → closeStatusOf(p)：isBackfill 或已过 bidDeadline 才 canClose；
    无 bidDeadline 视为已过（否则老项目永远关不掉）

POST /api/projects/:id/close  {mode, abandonReason, confirmText}
  → canClose=false 且 mode!=='abandon' → 403 DEADLINE_BLOCK
  → mode==='abandon' 必须给 abandonReason → 否则 400 NEED_REASON
  → confirmText 必须严格等于「关闭归档」→ 否则 400 NEED_CONFIRM
  → archiveProject() 传 {note, sessions: listSessions(pid), clearProject: true}（v1.2.5），写 closedBy / abandonReason
  → 复制 01-05 目录 + 06过程记录/（copyProcessTo）
  → v1.2.5：copy 完调 verifyArchiveCopy() 逐文件核对数量与大小，
     ok 才 clearProjectFiles() 清空 项目/<dir>/01~05（目录保留），
     返回值多一个 cleared:{ok, removed} 或 {ok:false, reason, bad[]}；核对不过就不清空

POST /api/projects/:id/reopen（v1.2.5）
  → STAGE_SUBS.some(子目录不存在或为空) 时 restoreProjectFiles(p)
      从 归档/<relDir>/01~05 复制回 项目/<p.dir>/（06过程记录/项目摘要.json/归档说明.txt 不回填）
  → restored.ok === false → 409 ARCHIVE_MISSING（不把状态改成 active，避免「在做但没文件」）
  → 成功 → UPDATE status='active', closedAt=NULL，返回 {ok:true, restored:{ok, files}}

只读闸门
  createServer 里：非 GET 且路径里带 p_ 开头的项目 id 时调 readOnlyBlock()
  RO_ALLOW 白名单：/reopen、/export、/indep/export
  → 命中 403 ARCHIVED_READONLY
~~~

### 3.8 知识卡提炼与检索（v1.2.0）

~~~
归档

  → archiveProject() 返回 knowledgeChapters（tech/biz 章节标题 + 正文，各截 2 万字）
  → apiReady() 且有章节时 startCardTask(p, knowledgeChapters, {}) → cardTaskId
  → 前端收到 cardTaskId 后立刻开始轮询 /api/card-tasks/:id

     输出 {cards:[{type,title,body,tags,quality,page}]}，type ∈ 7 种

~~~

### 3.12 核查候选的四道闸（v1.2.1）

`lib/check.mjs` 的 `listSources(project)` 只扫 `03制作`（draft）与 `04核查`（check），按顺序过闸：

```
TENDER_NAME_RE = /招标文件|招标公告|投标邀请|采购文件|磋商文件|询比文件|谈判文件|竞价文件|资格预审文件|澄清|答疑|更正公告|中标公告|中标结果/

闸门1  文件名命中 TENDER_NAME_RE
       → { origin:'tender', excluded:true, final:false, label:'这是招标类文件，不是投标文件' }
闸门2  内容 SHA-256 与 01招标文件 下任一文件相同（tenderFingerprints 递归扫，跳过 >200MB）
       → { excluded:true, label:'这份和招标文件内容完全一样（xxx），不是投标文件' }
闸门3  origin==='other'（名字不标准）不再 final=true
       → { final:false, label:'名字不标准，不确定是不是投标文件', suspect:true }
```

### 3.16 异步 Word 转换与核查任务生命周期（v1.2.3）

**为什么要改**：v1.2.2 之前 `docToDocx/docxToPdf` 用 `execFileSync` 同步调 PowerShell→Word COM，转换期间 Node 事件循环完全冻结。52.21MB 的 docx 转 PDF 要 26 秒，这 26 秒里服务连 `/api/check-tasks/:id` 都答不了，前端 2 秒轮询全部挂起 → 页面永远停在「正在读取文件」。

**现在的分工**：

| 文件 | 职责 |
|---|---|
| `lib/convert.mjs` | `runPs(psLines, opts)` 写带 BOM 的 .ps1 → `spawn` 子进程 → 返回 Promise；`timeoutMs = opts.timeoutMs \|\| (loadConfig().convertTimeoutSec \|\| 480)*1000`；超时 `code='CONVERT_TIMEOUT'`、取消 `code='CONVERT_CANCELLED'`；每 3 秒 `opts.onProgress(已等秒数)`；输出先写 `.part`，成功才 rename |
| `lib/extract.mjs` | `docToDocx/docxToPdf` 只剩一行兼容包装：`return import('./convert.mjs').then(m => m.docToDocxAsync(...))`。**所以所有调用方必须 await** |
| `lib/check.mjs` | 任务编排、阶段进度、看门狗、停止、自愈 |

**任务对象新增字段**：`stage`（读取文件/格式检查/逐条核对/模拟评标）、`docIndex`、`lastTickAt`、`stopRequested`、`_abort`（AbortController，**persist 时必须剔除**，否则序列化成 `{}`）。

**关键常量**：`STALL_MS = 180*1000`（3 分钟无进展判僵死）、`WATCH_MS = 10*1000`（看门狗间隔）。

**状态机**：`running → done / stopped / error / stalled`。

- `stopCheckTask(id)`：置 `stopRequested`、`message` 改成「正在停止…（等当前这一步收尾）」、`_abort.abort()`。内层 catch 必须认三种取消信号：`e.code === 'STOPPED' || e.code === 'CONVERT_CANCELLED' || t.stopRequested` 都要 rethrow，否则会被当成「这份文件读不了」吞掉、照常往下跑并写出一份假的「全部通过」。
- `getCheckTask(id)`：内存没有就读 `数据/核查/.tasks/<id>.json`；文件里还是 running 但没有内存实例 → 直接改判 `stalled`（文案「上次核查没跑完（工作台中途重启或转换卡住了）」、`lastTickAt=0`）。
- `healStaleTasks()`：`server.mjs` 启动时扫一遍 `.tasks`，running 全改 stalled，日志「[twb] 上次有 N 个核查任务没跑完，已标记为「上次没跑完」」。**注意这个函数必须在 server.mjs 顶部 import，否则静默不生效。**
- `killOrphanAutomation()`：`server.mjs` 启动时调一次，用 `Get-CimInstance Win32_Process` 找 `CommandLine -like '*/Automation*'` 的 WINWORD 并 killTree；**只杀自动化进程，用户手开的 Word 不动**。工作台被强杀后会残留这些进程，拖慢甚至卡死后续转换。

**降级**：`convertTimeoutSec` 默认 480 秒（设置页可改 60~3600）。超时后 `checkOneDoc` 返回 `{degraded:true, checksOmitted:['空白页（需要真实排版）','页码连续性（需要真实排版）','封面正副本标注（需要真实排版）']}`，`checks` 改用 `textOnlyRuleCheck`，其余照常；任务结束时 message 追加「（N 份文件 Word 转 PDF 失败，只做了文字类核查：空白页、页码、封面标注这三项没查，请人工补看）」。

**前端**：`viewCheck()` 的 running 分支渲染 `.ck-prog` 进度卡（`#ckStage/#ckMsg/#ckElapsed/#ckDocIdx` + `#btnStopCheck`）；`ckPoll` 每 2 秒只就地更新这四个 id，不整页重画；连续 3 次取进度失败才停轮询并提示。`btnRunCheck` 在已有 running 且 `idleSec<180` 时先 confirm 再 stop 重开。

### 3.18 归档清空与补录停止（v1.2.5）

**归档清空（B 方案，归档成为唯一副本）**

`lib/archive.mjs` 导出：

- `STAGE_SUBS = ['01招标文件','02分析','03制作','04核查','05递交']`（原 archiveProject 里写死的数组提出来，server 端判断与恢复共用）。
- `verifyArchiveCopy(project)`：按子目录逐个文件比对「归档里有 + 大小一致」，返回 `{ok, reason, total, bad[]}`（bad 最多 20 条）。relDir 从 `project.archiveNote` 按 `'||'` 切后半段取，所以调用时要给带 archiveNote 的副本：`verifyArchiveCopy({ ...project, archiveNote: '||' + relDir })`。
- `clearProjectFiles(project)`：清空 `项目/<dir>/01~05` 的**内容**，目录保留，返回移除条目数。
- `archiveProject(project, db, {clearProject:true})`：复制完成后先 verify 再 clear，`cleared` 随返回值出去。

关键取舍：**核对不通过绝不清空**（宁可多留一份，也不删没备份的东西）。因为一旦清空而归档又缺文件，用户的原件就真没了。

**归档回落（清空后仍要看得到文件）**

- `server.mjs` `fileAbs(f)`：先 `path.join(ROOT, f.relPath)`，不存在时用 `archiveAbsOfRel(rel)` 换算成 `归档/<relDir>/<阶段>/<...>` 再试（`archiveAbsOfRel` 用 `SELECT * FROM projects WHERE dir = ?` 反查项目、取 archiveRelDirOf）。`GET /api/download` 同样处理，仍不存在才 404。
- `lib/analyze.mjs` `archivePathOf(project, f)`：runAnalysis 里 `const filePath = ...` 改为 `let`，不存在时回落归档，再不存在才报「招标文件已不在磁盘」。

**补录停止（整条链路补齐）**

以前 `web/app.js` 的 `confirmStopBackfill()` 只 `DELETE /api/projects/:id`，后台 IIFE 照跑、backfillTasks 里 `state` 一直是 `running`，于是左侧任务条一直显示、最后还会把删掉的项目重新建出来。v1.2.5 补齐四处：

1. `lib/analyze.mjs`：`stopAnalysisTask(taskId)` 置 `stopRequested` 并 persist；私有 `checkStop(task)` 抛 `Object.assign(new Error('已按要求停止'), {code:'STOPPED'})`；检查点插在分段循环开头、重试循环开头、评分表补跑前；`.catch` 里 `code==='STOPPED'` → `state='stopped'`（不是 failed）；评分表补跑的 `catch` 首行 `if (e && e.code === 'STOPPED') throw e;`，否则停止会被吞成「评分表补跑失败」。
2. `server.mjs` 补录任务对象加 `stopRequested` / `analysisTaskId`；`bfCheckStop(t)` 先 `stopAnalysisTask(t.analysisTaskId)` 再抛 STOPPED；七个阶段前与 20 分钟轮询循环内都插检查点；catch 里 `stopped` → `state='stopped'`、`message='已停止'`，随后照旧 `deleteProjectFully()` 清半成品，最终 message 为「已停止，补录项目已删除」。
3. `server.mjs` 新增 `POST /api/backfill/:id/stop`：任务不存在 404；已非 running 返回 `{ok:true, already:true, state}`；否则置 `stopRequested` + `message='正在停止…'` 并停内层分析任务。
4. `web/app.js` `confirmStopBackfill()`：先 `POST …/stop`，再每 500ms 轮询 `GET /api/backfill/:taskId` 最多 40 次，直到 `state !== 'running'` 才收尾（goHome + refreshProjects）；**不再直接 DELETE 项目**。`bfRun()` 的 tick 增 `t.state === 'stopped'` 分支复位 UI。`bfTaskOf()` 返回值补 `stopRequested`。

**为什么把停止做在「循环检查点」而不是 AbortSignal**：分析任务是「多段 AI 调用」的长流程，每段之间本来就有 await 边界，插布尔检查最省改动；AbortSignal 需要透传到 `callJson` 的 fetch，会牵动 ai/providers/config 三层，收益不明显。

| 独立编制生成/更新 | `draft` | 文本 | 条款原文（≤18000 字）+ 画像 + 知识库参考 + 对话要求 | JSON：{title, text, charts[], hints[]} |
| 图表设计 | `draft` | 文本 | 章节内容摘要 + 用户修改要求 | JSON：{chartType, title, caption, reason, spec} |
| 知识卡提炼（v1.2.0） | `card` | 文本 | 重要技术/商务章节标题 + 正文（6 章/45000 字一批） | JSON：{cards:[{type,title,body,tags,quality,page}]} |
| 章节性质复核（v1.2.0） | `draft` | 文本 | 章节标题 + 正文摘录前 260 字 | JSON：{roles:[{index, role}]} |

共同约定：

- 只用招标文件原文当依据，禁止通用模板（提示词里写了最高原则）。
- 长文档不整份送：先按「页级 bigram 相关度」挑页（pickPages），并保留 mustPages（索引页、报价页）。
- 被省略的页数会回传（omittedPages），界面上明确提示「有 N 页没放进本次范围，请人工确认」。
- 提示词要求 JSON 输出时，只在模型声明支持 `json:true` 时才带 `response_format:{type:'json_object'}`；解析侧一律从回复里抠第一个 {...} 或 [...]，再走 `repairJson` 抢救截断的 JSON。
- 调用失败先判断是不是「Key / 权限 / 余额 / 地址模型名」这类硬错；不是硬错就自动换列表里下一个可用模型重试（v1.2.3）。
- `reasoning_effort` 只对 DeepSeek 系列默认给 `'none'`，其它模型不主动带；被拒时自动去掉这两个可选参数重试一次。

## 七、已知边界

1. **扫描件识别先本机、后看图模型**（本机 OCR：Windows 自带识别优先，其次 Tesseract）：能识别出文字就不调模型；识别不出且你配了「能看图」的模型才发图，没配就只用本机结果并提示你人工补看。纯图片 PDF 的页数、字数统计以识别结果为准。
2. **docx/doc→PDF 依赖 Windows + 安装 Microsoft Word**（用 COM）；没装 Word 的机器上，核查中的 PDF 相关步骤、按页看原文会失败并给出中文提示（.doc 则直接读不了）。装 WPS 不算。
3. **AI 结论需人工复核**：逐条核查的「部分响应」大量来自电子文件无法体现的事项（装订、密封、现场递交、CA 证书），设计上就是提醒人工确认，不是判定。
4. **超长标书只核对相关页**：161 页的标书不会整份送 AI，而是在页级检索后取相关页；被跳过的页会在界面上写明。
5. **知识卡检索不是向量检索**（v1.2.0）：按二元组重合度 + 使用次数 + 质量分排序，几十个项目内够用，项目数上百后建议换向量库。
9. **知识卡提炼要花 AI 额度**：每个项目归档时按「6 章 / 45000 字」分批提炼，章节多的大项目会有几十次调用；提炼失败不影响归档，卡片为空时提示词就退化成纯策略。
10. **手工改过的卡不会被「重新提炼」覆盖**：想让它被替换，先手工删掉那张卡再提炼。
6. **中文语境**：板块、提示词、评分逻辑都按中国大陆政府采购/招标习惯写。
7. **图只能出示意图**（v1.1.2）：独立编制里的图是本机 SVG 渲染的流程图/架构图/甘特图/折线图这类示意图，不是照片级效果图；现场照片、设备照片仍需你自己提供。
8. **归档后只读**（v1.1.2）：归档项目的一切写操作被服务端拦掉（403 ARCHIVED_READONLY），要改必须先「重新打开」。
11. **查重只比「名称 + 编号」的规范化字符串**（v1.2.1）：名称差一个字（如多一个空格以外的差异、简繁体）仍可能被当成不同项目，需要人工判断。
12. **归档去重只对「之后新归档的」生效**（v1.2.1）：历史上已经写进同一文件夹的两份摘要，后一份已覆盖前一份，改代码也救不回来；这种只能在列表里看到 dupCount 提示。
13. **章节编号只认「标题文字开头」的编号**（v1.2.2）：编号写在标题中间（如「需求理解 9.1」）或单独一段（「9.1」独占一行、下一段才是标题）都认不出来，会退回自动编号或无编号；层级仍按 Word 标题样式判定，样式没设对的一律当正文。
14. **核查依赖本机 Word 转换**（v1.2.3）：转 PDF 需要 Windows + 装 Microsoft Word。转换本身已不阻塞服务，但机器上没装 Word 时仍然做不了空白页/页码/封面标注这三项，会降级成文字核查并明确提示。
15. **多模型只保证 OpenAI 兼容协议**（v1.2.3）：能填的都是 `/chat/completions` 形式的接口（OpenAI、DeepSeek、通义 DashScope 兼容模式、Moonshot、智谱、Ollama、LM Studio、vLLM）。Anthropic / Gemini 原生协议不支持，需要各自的转换层。
16. **看图能力靠手工勾选**（v1.2.3）：模型是否「能看图」由你在设置页那一行的勾选框决定，不会自动探测；勾了但其实不支持，扫描页会识别失败并回落到本机 OCR。
17. **归档后 `项目/` 里的原件会被清空**（v1.2.5）：核对（文件数 + 大小）全部一致才清空，目录保留；核对不过则本次不清空。归档文件夹是唯一副本，**单独删归档文件夹等于删项目资料**。已归档项目若要重新分析/核查，走归档回落路径读取。
18. **补录停止是「协作式」**（v1.2.5）：停止请求只设标记，任务在下一个检查点退出；若正卡在一次耗时的 AI 调用里，要等这次调用返回/超时才会真正停下（最长约 5 分钟，即 callJson 的 timeoutMs）。停下来的状态是 `stopped` 而非 `failed`。

## 八、开发与调试

~~~bash
# 直接跑（开发模式，改前端刷新即可，改后端要重启）
node app/server.mjs

# 指定数据根目录（不污染仓库）
TWB_ROOT=/tmp/twb-test node app/server.mjs

# 检查接口是否活着
curl http://127.0.0.1:7830/api/health
~~~

常见故障：

- 7830 被占用：改 app/config.json 的 port（前端会跟着 /api/health 的返回走）。
- Word 转换卡住：任务管理器结束 WINWORD.exe 后重试（脚本以只读方式打开、不保存）。
- 分析结果是空：先看数据/文本/<fileId>.json 有没有 pages；没有就是抽取失败（PDF 加密或非标准格式）。
